📋 Product & Architecture Spec — v3.0.1 (Final Production Spec)

SAFAR
J&K Transit Compliance Platform

Transparent fares. Hybrid payments. Regulatory compliance engine.
The operating system for J&K's unorganized transit layer — Matadors, Mini-Buses, Shared Vans, and Rickshaws.

Three Pillars

Everything in SAFAR traces back to three pillars. Every screen, every data model, every API endpoint exists to serve one of these.

Pillar 1

Transparent Fare Calculation

🚏 Boarding Stop → 🚏 Deboarding Stop → 📐 Route Segments → 📏 Actual Distance → ₹ Regulated Fare

Shown to the passenger before they board. No ambiguity. Distance is walked along actual route segments, not a straight-line approximation. Transit Regulatory Council slab rates apply automatically. Vehicle multipliers adjust for Matador, Mini-Bus, Tata Magic, Shared Van, Rickshaw, E-Rickshaw, and Maxicab.

Pillar 2

Hybrid Payment (Cash + Digital)

💳 Digital locks fare 💵 Cash receipt + QR 📊 Same Audit Trail

Digital locks fare before boarding. Cash generates a printed receipt with QR. Both feed the same audit trail. Senior citizens pay cash without friction. Overcharging still gets logged — the compliance engine sees every trip regardless of how the passenger paid.

Pillar 3

Regulatory Compliance Engine

🏛️ Transit Permit Registration → ⚠️ Auto-Detect → 📊 Categorise → 📤 Export to Transit Council

Operator Transit Permit registration verified on every trip. Overcharges auto-detected, categorised by severity, and exported to transport authority. Positions Safar as infrastructure, not a consumer app. Regulatory can query compliance metrics in real time.

🤖 AI Differentiation Layer

SAFAR's AI assistant isn't a chatbot bolted onto a fare calculator. It's a context-aware transit copilot that understands J&K route geography, Transit Regulatory Council fare rules, and real-time bus occupancy — responding in Hindi, Kashmiri, and English.

Fare dispute resolution Route recommendation ETA prediction Anomaly detection SOS triage

🧮 Fare Calculation Logic

function calculateFare(region, terrain, distance_km, vehicle_type, concession_pct) {
  // 1. Lookup slab (flat bands ≤ 20km)
  const slabs = { 3: 9, 5: 14, 10: 17, 15: 20, 20: 26 };
  const rates = { Kashmir: { plain: 1.40, hilly: 1.70 },
                   Jammu:   { plain: 1.35, hilly: 1.65 } };

  let base_fare;
  if (distance_km <= 20) {
    base_fare = lookupSlab(slabs, distance_km); // round up to next slab
  } else {
    base_fare = slabs[20] + (distance_km - 20) * rates[region][terrain];
  }

  // 2. Apply vehicle multiplier
  const multipliers = { matador: 1.0, minibus: 1.0, tatamagic: 1.10, sharedvan: 1.15, rickshaw: 1.0, erickshaw: 1.15, tavera: 1.25 };
  base_fare *= multipliers[vehicle_type] || 1.0;

  // 3. Apply concession AFTER multiplier
  const total = base_fare * (1 - concession_pct / 100);

  return { base_fare: Math.round(base_fare), total_fare: Math.round(total) };
}

Compliance Engine

The compliance engine is the invisible backbone of Pillar 3. It classifies every cash transaction into a severity tier, logs operator patterns, and generates export-ready reports for J&K Regional Transport Authority.

⚖️ Discrepancy Severity Tiers

Comparison: actual_paid_paise vs. calculated_fare_paise (difference = actual − calculated).

Compliant (= 0)
No action
Rounding (≤ 5p)
Ignored — noise
Minor (≤ 25p)
Logged for metrics, no escalation
Major (> 25p)
Log + Flag + Prompt user report + Transit Permit export
Undercharge (< 0)
Passenger benefit — log only, no penalty
